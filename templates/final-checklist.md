# 最终检查清单

这份清单将 ECC 的验证、审查和安全门槛压缩成考试最后 10 分钟可用的一轮检查。

## 运行

- [ ] 项目可以用一条清晰的命令启动。
- [ ] 主 happy path 能端到端跑通。

## 契约

- [ ] 输入和输出形状是稳定的。
- [ ] README 与实际行为一致。
- [ ] 契约没有暗示任何根本没有实现的功能。

## 测试

- [ ] 在实现之前就定义了最小验收测试或验证方式。
- [ ] 已存在关键路径测试。
- [ ] 如果这是修 bug，已经在修复前补上回归测试或明确的回归证明。
- [ ] 最重要的检查在最后一次代码修改后重新运行过。
- [ ] 任何刻意省略的测试覆盖都已经写明。

## 安全

- [ ] 没有遗留硬编码密钥。
- [ ] 用户输入在系统边界完成校验。
- [ ] 没有暴露敏感错误细节。

## 交付质量

- [ ] 范围和非目标是明确的。
- [ ] README 或交接说明写清了测试内容、覆盖的关键路径，以及未测试内容。
- [ ] 已写明已知限制。
- [ ] 可选工作或未完成工作有明确标注。
- [ ] 交付路径里没有平台化或营销噪音。

## 仓库自检

- [ ] `./scripts/verify.sh` 通过。

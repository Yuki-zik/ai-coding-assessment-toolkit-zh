# 中文提示词模板

这份文件提供可直接复制的中文提示词，面向 2 小时的 agent 项目笔试。

使用建议：

- 先选一个最贴近当前阶段的模板
- 把方括号里的占位符替换成你的题目、仓库、报错或约束
- 不要一次把 3 个阶段混在一个提示词里
- 如果 AI 开始发散，就回到“范围收敛”或“调试”模板重新约束

## 1. 通用开题

```text
你现在在帮助我完成一个 2 小时 AI 编码笔试题，题目方向是 agent 相关项目。

请严格按下面顺序工作：
1. 先检查项目根目录是否存在 `agent/project.md`、`agent/tasks.md`、`agent/timeline.md`、`agent/agents.md`，如果没有就立即创建。
2. 先读取 `agent/timeline.md` 和 `agent/tasks.md`，总结当前状态。
3. 先用中文复述题目，确认你理解的目标。
4. 判断它更像哪一种架构类型：
   - 网关 / 代理 / 聚合器 / BFF
   - 工具调用型助手 / 函数调用型 agent
   - 检索 / 知识助手 / 轻量级 RAG
   - 工作流 / 规划-执行器 / 任务自动化
5. 先做范围收敛：给出 MVP 范围、非目标、主成功路径。
6. 先给出最小文件树。
7. 先定义最小契约：
   - 端点 / 接口
   - 输入 / 输出
   - 工具契约（如果有）
   - 状态流转
   - 错误处理
   - 假设
8. 再开始实现最小可运行主链路。
9. 只补 1-3 个关键路径测试。
10. 最后输出 README 需要写的要点，并更新 `agent/tasks.md` 和 `agent/timeline.md`。

规则：
- 优先复用仓库已有代码和依赖，不要先造新框架
- 优先单主 agent 工作流，不要默认做多 agent 系统
- 优先主成功路径，不要一开始追求大而全
- 如果题目像平台，主动裁剪成一个最小可运行服务或主循环

题目如下：
[把题目贴在这里]
```

```text
- 不要默认加缓存、队列、插件系统、后台任务、管理后台、复杂可观测性
```

## 3. 先定契约

```text
先不要实现，先帮我定义这个题目的最小契约。

请输出一份最小契约，至少包括：
- 入口点 / 端点 / 接口
- 方法 / 调用方式
- 输入模式
- 输出模式
- 工具契约（如果有）
- 状态读取 / 写入
- 主流程
- 错误契约
- 假设
- 明确不支持什么

要求：
- 契约要足够小，能支撑 2 小时 MVP
- 输出形态要稳定，便于后面写测试
- 不要给出平台级抽象，只定义当前题目必须的契约
```

## 4. Debug 启动失败

```text
我现在不需要大改架构，我需要你用最快路径帮我恢复主链路。

请按下面方式调试：
1. 先复述你理解的失败现象
2. 判断它属于哪类问题：
   - 启动失败
   - 依赖 / 配置失败
   - 契约不匹配
   - 构建 / 类型检查失败
   - 测试失败
3. 先找最小证据路径，不要全仓库乱改
4. 一次只修一个阻塞点
5. 每修一次，只跑最小必要验证命令
6. 最后告诉我：
   - 根因
   - 修改了什么
   - 还有什么风险暂时没处理

限制：
- 不要顺手做大重构
- 不要为了“更优雅”扩大差异范围
- 优先恢复主链路，而不是做清洁工作

报错信息：
[贴报错]

相关文件 / 命令：
[贴这里]
```

## 5. Debug 测试失败

```text
我现在遇到测试失败。请按“最小差异修复”思路帮我处理。

请这样工作：
1. 先解释这个测试在证明什么
2. 判断是测试错了、契约变了，还是实现坏了
3. 给出最小修复方案
4. 修复后只跑最相关的测试
5. 告诉我这次失败暴露了什么契约风险

要求：
- 不要为了让测试绿而破坏真实行为
- 不要直接删测试，除非你能证明测试目标本身错了
- 优先保证主成功路径和一个关键失败路径

失败测试输出：
[贴这里]
```

## 6. 网关 / 代理 / BFF

```text
1. 判断它更接近代理、网关、聚合器还是 BFF
2. 给出最小交付边界
3. 设计一个最小契约
4. 设计一条主成功路径
5. 指出最容易过度设计的点
6. 给出最小测试集合

默认偏好：
- 一个入口
- 一层校验
- 一个或两个小适配器
- 一个统一的响应形态
- 一个统一的错误形态

不要默认做：
- 动态路由 DSL
- 插件系统
- 流式传输 + 缓存 + 聚合一起上
- 复杂重试或熔断系统

```

```text
- 工具名稳定
- 工具输入窄
- 输出形态可预测
```

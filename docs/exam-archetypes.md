# 考试架构类型

本文档是 ECC 的架构、脚手架构建、后端、API、检索与文档查询材料在考试路径上的压缩版。

主要继承来源：

- `legacy/ecc-source/agents/architect.md`
- `legacy/ecc-source/skills/agent-harness-construction/SKILL.md`
- `legacy/ecc-source/skills/backend-patterns/SKILL.md`
- `legacy/ecc-source/skills/api-design/SKILL.md`
- `legacy/ecc-source/skills/iterative-retrieval/SKILL.md`
- `legacy/ecc-source/agents/docs-lookup.md`
- `legacy/ecc-source/skills/documentation-lookup/SKILL.md`

这套脚手架只支持四类高频 agent 项目架构类型。它们共享一条可复用主线，继承自 ECC 的 planner、architect 和 verification 流程：

1. 用自己的话复述题目
2. 选择能闭环的最窄架构类型
3. 定义 MVP 范围和非目标
4. 定义 contract 和停止条件
5. 构建最小主循环
6. 增加 1-3 个关键路径测试
7. 基于真实证据撰写最终 README

## 1. 网关 / 代理 / 聚合器 / BFF

### 最小闭环

- 接收一个请求
- 校验并授权
- 调用一个上游服务或一小组适配器
- 规范化结果
- 返回稳定的响应结构

### 非目标

- 计费、多租户、管理面板
- 动态策略引擎
- 插件市场
- 分布式编排

### 常见过度设计陷阱

- 过早构建通用适配器框架
- 一次性加入流式、缓存和重试
- 混合 gateway、产品 UI 和平台控制面问题

### 可复用结构

- 一个入口处理器
- 一个规范化层
- 一个适配器边界
- 一个错误格式

### 来自 ECC 的复用信号

- 使用 API 风格的稳定成功和错误结构
- 在入口点校验输入
- 显式保留适配器，不要把它们藏在通用插件层后面

## 2. 工具调用助手 / Function-Calling Agent

### 最小闭环

- 接收用户请求
- 选择一个工具或一小组固定工具
- 校验工具输入
- 调用工具
- 必要时返回有依据的答案和基础 trace 或理由

### 非目标

- 开放式工具生态
- planner 树和递归执行
- 自主长时间运行循环

### 常见过度设计陷阱

- 构建通用 agent 框架
- 在没有题目压力的情况下加入记忆、反思和评分
- 发明复杂的工具注册表

### 可复用结构

- 请求解析器
- 工具选择器
- 工具适配器
- 响应规范化器

### 来自 ECC 的复用信号

- 使用固定工具名和窄输入 schema
- 返回确定性的工具输出
- 明确写出失败行为，而不是含糊的恢复文案

## 3. 检索 / 知识助手 / 轻量 RAG

### 最小闭环

- 接收一个问题
- 查询一个小型文档集或检索源
- 选出少量相关片段或记录
- 使用检索到的上下文作答
- 清晰展示空结果或无结果行为

### 非目标

- 完整的摄取流水线
- 向量平台运维
- 多租户记忆系统

### 常见过度设计陷阱

- 构建摄取、同步和管理工具
- 在基础闭环工作之前过度优化排序
- 假装一个小查找任务需要完整 RAG 平台

### 可复用结构

- 检索器
- 选择器或排序器
- 答案组装器
- 一致的引用或来源元数据结构

### 来自 ECC 的复用信号

- 先做宽检索，只有首轮不够时才收窄
- 当 API 或库对版本敏感时，使用当前文档或一手来源
- 停在“足够好”的上下文，不要为了它构建完整检索平台

## 4. 工作流 / Planner-Executor / 任务自动化

### 最小闭环

- 接收一个任务
- 生成简短、确定性的计划
- 按顺序执行每一步
- 记录状态
- 返回最终结果或第一个明确失败

### 非目标

- 分布式队列
- 长时间运行的调度器
- 多 agent 执行图

### 常见过度设计陷阱

- 把一个短任务执行器做成工作流平台
- 过早加入可恢复性、重试和分支
- 为单一考试题过度建模状态机

### 可复用结构

- 规划器
- 执行器
- 状态追踪器
- 报告器

### 来自 ECC 的复用信号

- 除非题目明确要求自适应行为，否则保持循环确定性
- 返回第一个明确失败，不要用重试或编排把它遮住
- 只追踪完成考试任务所需的状态

## 共享非目标

在这四类 archetype 里，都要显式避免：

- 平台化安装或插件系统
- 多 agent 控制面
- 大型动态工具注册表
- 完整的记忆或摄取栈
- 除非题目直接要求，否则不要加入可观测性、计费、管理或多租户特性

## 常见过度设计陷阱

- 把单个考试闭环做成可复用框架
- 在实现后才把 contract 说清楚
- 让工具或路由数量把行动空间撑得过大
- 把“以后可能有用”与“现在必须工作”混在一起
- 把检索、编排和文档查询误当成核心产品需求

## 本仓库明确不包含

以下内容被有意排除在 2 小时考试脚手架之外：

- 多 agent 编排平台
- 自主 swarm
- 完整记忆或 RAG 平台
- 多租户、计费或管理系统
- 复杂的可观测性与调度栈
